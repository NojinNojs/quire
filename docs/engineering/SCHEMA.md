# Quire backend schema

The authoritative PostgreSQL schema is in [`supabase/migrations/`](../../supabase/migrations/), applied in filename order. Supabase Auth provides identities through `auth.users`. This reference summarizes the resulting tables; the migrations define exact defaults, constraints, triggers and policies.

## Tables

### `profiles`

| Column | Type and contract |
|---|---|
| `id` | UUID primary key, references `auth.users`, cascade delete |
| `display_name` | nullable text |
| `annual_goal` | nullable integer, 1 to 500 |
| `created_at` | non-null timestamp with time zone, default `now()` |

The new-user trigger creates a profile and streak row.

### `works`

| Column | Type and contract |
|---|---|
| `id` | UUID primary key, generated by default |
| `title` | non-null text |
| `author` | nullable text |
| `title_key` | generated normalized title |
| `created_by` | nullable profile UUID, set null on deletion |
| `created_at` | non-null timestamp with time zone, default `now()` |

`(title_key, author)` is unique. Authenticated users may read works; writes are scoped to the creator.

### `books`

| Column | Type and contract |
|---|---|
| `id` | UUID primary key, generated by default |
| `owner` | non-null profile UUID, cascade delete |
| `work_id` | nullable work UUID, set null on deletion |
| `title` | non-null text |
| `author`, `publisher`, `city`, `edition` | nullable text |
| `year` | nullable integer, 1000 to 2100 |
| `pages` | nullable positive integer; unknown is not a fabricated total |
| `isbn`, `ddc`, `language` | nullable text |
| `cover_url`, `cover_path` | nullable text, catalogue URL and private storage path |
| `status` | non-null text, default `want`; `want`, `reading`, `finished`, or `wishlist` |
| `rating` | nullable integer, 1 to 5 |
| `notes` | nullable text |
| `started_at`, `finished_at` | nullable dates |
| `created_at`, `updated_at` | non-null timestamps with time zone, default `now()`; update trigger maintains `updated_at` |

Partial unique indexes enforce one `reading` book per owner and unique non-null ISBN per owner. Owner/status and owner/DDC indexes support collection queries. The language migration removes the original default and non-null restriction.

### `progress_log`

| Column | Type and contract |
|---|---|
| `id` | UUID primary key, generated by default |
| `owner` | non-null profile UUID, cascade delete |
| `book_id` | non-null book UUID, cascade delete |
| `day` | non-null date |
| `pages` | non-null positive integer |
| `created_at` | non-null timestamp with time zone, default `now()` |

`(owner, book_id, day)` is unique; `(owner, day)` is indexed.

### `streaks`

| Column | Type and contract |
|---|---|
| `owner` | profile UUID primary key, cascade delete |
| `current`, `longest` | non-null non-negative integers, default 0 |
| `last_day` | nullable date |
| `restore_left` | non-null integer from 0 to 1, default 1 |
| `restore_month` | nullable text month marker |

### `book_photos`

`id` is a generated UUID primary key; `owner` and `book_id` are non-null UUID foreign keys with cascade delete. `storage_path` is non-null text, `caption` is nullable text, and `created_at` is a non-null timestamp defaulting to `now()`. This table does not imply a configured page-photo bucket or extraction service.

## RLS and reading RPC

All listed public tables have row-level security. Profile select, insert and update are owner-scoped; books and photos are owner-scoped; streaks and progress are readable by their owner. Progress writes are not exposed through an owner write policy.

`log_pages(p_book uuid, p_pages int, p_day date default current_date)` returns `streak_current`, `streak_longest` and `restored`. It rejects unauthenticated requests, non-positive pages and books not owned by the caller. It adds pages to the existing owner/book/day row, starts a `want` book as `reading`, and updates the streak in the same transaction. One restore per calendar month can bridge a single missed day; the migration defines exact handling of dates and quotas. The one-active-book index also applies to the status update.

Deleting a book cascades its progress and triggers a streak rebuild from remaining distinct reading days. See `20261101000000_book_delete_streak.sql` for the calculation.

## Storage and client access

The private `covers` bucket accepts WebP and restricts objects to an owned book at `{owner}/{book_id}/cover.webp`; the client uses signed URLs. No `pages` bucket is established by the migrations.

Catalogue lookup runs in the client against Google Books and Open Library. Other data operations use the Supabase client, database policies and RPC. No `/health`, `/catalog`, `/extract` or `/streak/tick` Elysia endpoints are implemented here.
